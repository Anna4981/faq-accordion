An accordion is a stacked list of headings. Clicking a heading reveals or hides the content beneath it, so people can scan the questions and only read the answers they need.

classList.toggle("open") adds the class if the element does not have it, and removes it if it does. It returns true when the class was added and false when removed.

A <button> is focusable with the Tab key and can be activated with Enter or Space by default. Screen readers also announce it as an interactive control. A plain <div> needs extra code to get any of this.

Event handling means running code in response to something that happens on the page, such as a click, key press or scroll. You attach a function to an element with addEventListener, and the browser calls it when the event occurs.

It is a design choice. This page opens one answer at a time to keep the list tidy. Change ALLOW_MULTIPLE to true in script.js if you want several answers open together.

The open item gets an active class. CSS uses it to add an orange accent bar, tint the question, and rotate the plus icon into a cross.

The container is fluid with a maximum width, text sizes use clamp(), and a media query reduces padding on narrow screens. Touch targets stay large enough to tap comfortably.

aria-expanded tells assistive technology whether the answer is open, and aria-controls links the button to the panel it controls. A visible focus outline helps keyboard users see where they are.

JavaScript only toggles a class. CSS handles the smooth open and close, which keeps the script short and lets the browser optimise the animation. Users who prefer reduced motion get no animation.

MDN Web Docs has clear pages on Element.classList and EventTarget.addEventListener. Both are good references for this project.
